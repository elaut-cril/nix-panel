# NIX Panel 2.1.9 — security audit

Проверка относится к серверной части и файловому менеджеру. Remote намеренно не анализировался глубже, как просил пользователь.

## Исправлено

1. **Эскалация через `permissions.admin`** — panel-created accounts больше не могут получить административную capability через API. `checkPerm('admin')` принимает только `installer_admin`.
2. **Второй администратор** — при обнаружении более одной записи с `role: "admin"` панель переходит в fail-closed режим и показывает `block.html`.
3. **Резервный пароль** — генерируется один раз при полной установке 2.1.9+, 35 символов `[A-Za-z0-9]`; на сервере хранится только salted SHA-256 hash.
4. **Безопасное обновление** — обновление с версии ниже 2.1.9 запрещено: требуется полная переустановка для получения резервного секрета.
5. **Аварийная блокировка** — installer admin может заблокировать панель; существующие Socket.IO-соединения разрываются.
6. **Файлы NIX** — panel-created users получают `403 Отказано в доступе` при обращении к каталогу установки; проверка учитывает realpath и существующие symlink-цепочки.
7. **ОС-права** — установка делает каталог панели недоступным для OS-пользователя `nobody`, под которым запускается ограниченная консоль panel-created account.
8. **Task Manager** — panel-created users могут смотреть метрики, но завершать процессы может только installer admin.
9. **Wake-on-LAN command injection** — заменён shell `exec()` на `execFile()` и строгую проверку MAC.
10. **Архивная распаковка** — shell-команды `tar/unrar/7z/mount` больше не строятся строковой конкатенацией; используются argument arrays.
11. **Upload filename traversal** — имена загружаемых файлов нормализуются через `basename`.
12. **Chat uploads** — `/uploads` требует право `chatRead`.
13. **Глобальные кнопки** — создавать/изменять/удалять глобальные кнопки может только пользователь с соответствующим правом.
14. **Темы** — встроенные темы остаются личной настройкой, создание/удаление пользовательских общих тем ограничено.
15. **Session secret** — для новой установки генерируется случайный секрет; на безопасном обновлении существующий секрет сохраняется.
16. **Cookie** — включены `HttpOnly` и `SameSite=Lax`.
17. **Brute-force** — введено ограничение неудачных попыток входа на пару IP+логин.
18. **Security events** — успешные и неудачные попытки входа записываются в отдельный файл, доступный только installer admin через API.

## Важное ограничение модели прав

Права файлового менеджера по-прежнему являются сильными полномочиями: пользователь, которому администратор выдал `filesUpload/filesDelete/filesArchive/filesClipboard`, может изменять большую часть файловой системы, кроме защищённой установки NIX. Поэтому эти права следует выдавать только доверенным пользователям.

`console` для panel-created users запускается от `nobody`, а не от root. Это отдельная граница безопасности.

## Remote

Remote намеренно не входил в аудит обходов прав. Его канал должен рассматриваться как отдельный privileged subsystem и доступен только через существующую permission boundary.
